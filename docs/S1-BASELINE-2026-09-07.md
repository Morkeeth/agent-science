## What a user gets today

**1. Cold.** All five: `NOT_CLEARED / not_in_registry / tier=free / source=dictionary_miss`.
With no provider key there is no path from a cold registry to an answer. A named source
must be supplied (`ingest`) or live discovery enabled.

**2. After verifying each claim against its named source.** All five `SOURCED`, real
spans, real URLs.

**3. Repeat ask.** All five come back `SOURCED / GREEN / tier=free`, from
`source=registry` or `source=dictionary_exact`. Reuse works.

**4a. Same question again.** `SOURCED`, `tier=free`, `source=dictionary_exact`.
No age. No fetch time. No content hash. Nothing that lets a reader judge whether the
evidence is still current.

**4b. Related but different question.** `NOT_CLEARED / not_in_registry`, and
**`candidates offered: 0`**. `search_registry` LIKE-matches the whole normalised query
string, so a real second question matches nothing and the second step of the journey
returns an empty pane.

**5–6. Synthetic source change** (labelled synthetic: the cached snapshot for
sqlite.org/copyright.html is replaced with text that does not contain the dedication
sentence). Ask #1 again:

```
{"label":"SOURCED","verdict":"GREEN","cost_tier":"free","source":"dictionary_exact",
 "citation_url":"https://www.sqlite.org/copyright.html","span":"Home Menu About …"}
```

**Identical to before the change. Silent. No warning, no re-read, no flag.**

**7. Re-verification command.** None. There is no `recheck` on the websearch path.
`cases.refresh` does source-change to dependent-decision flagging for research cases
only; the registry the ordinary websearch, CLI and MCP path reads has no equivalent.

## The gap, stated once
The reusable claim database reuses forever and never asks whether the evidence still
holds. Freshness is absent from the result, and a changed source changes nothing.
