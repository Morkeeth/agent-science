# Stranger-value auditor checks — what makes an agent-setup auditor worth running on a repo you've never seen
Date: 2026-08-24 · Lane: RESEARCH (theory/market) · Method: 6 web searches + 5 page/source fetches + competitor source-code read (ctxlint via GitHub API)

Format: one claim per line, tagged, with source URL. [measured] = quantitative primary source; [asserted] = practitioner claim, no measurement; [verified-source] = read the competitor's actual code; [inference] = my bridge, labeled.

## Q1 — How context files lie to agents (frequency x harm)

- [measured] Most of 3,000+ GitHub projects contain at least one outdated code-element reference in their docs at some point in history; >2/3 of surveyed developers believe their system documentation is outdated. Measured on GENERAL repo docs (READMEs/wikis), not agent context files. — https://link.springer.com/article/10.1007/s10664-023-10397-6 (also https://arxiv.org/pdf/2212.01479)
- [measured] Docs go stale "silently" — no crash or error signals staleness; developers are unaware their code change outdated the doc. Same study, general docs. — https://arxiv.org/pdf/2212.01479
- [measured] 2,303 agent context files across 1,925 repos: test procedures (75.9%), implementation details (70.8%), architecture (68.1%) are the dominant content; files "evolve like configuration code through frequent, small additions." No staleness RATE measured for agent files specifically. — https://arxiv.org/abs/2511.12884
- [inference] Bridge: agent context files are dominated by exactly the content classes (commands, paths, architecture) that the general-docs study shows rot in most projects, and they accrete via small additions without curation — so agent-file drift is near-certain at scale, though no one has yet measured its rate directly. — inference from the two studies above
- [asserted] "Stale paths and renamed scripts are the most common failure mode of AGENTS.md files." — https://www.betterclaw.io/blog/agents-md-best-practices (echoed by https://www.tembo.io/blog/agents-md)
- [asserted] Harm mechanism, stale command: "A stale command in AGENTS.md is worse than no command because the agent wastes time running it, then starts improvising... the agent loses confidence in all guidance" — stale guidance teaches the agent that instructions are advisory, not constraints. — https://www.agentlint.app/blog/writing-a-good-agents-md/
- [asserted] "Architectural drift" ("the architecture changed but CLAUDE.md did not") is "the most common form of CLAUDE.md decay, and the hardest to notice" — causes wrong file placement and references to nonexistent paths. — https://www.aicodex.to/articles/claude-md-maintenance
- [asserted] Four decay modes ranked by that article: architectural drift (most common, hardest to notice), dead instructions (obsolete commands/paths), contradictory instructions, file bloat past ~200 lines / ~50 instructions. — https://www.aicodex.to/articles/claude-md-maintenance
- [asserted] Instruction-budget harm: frontier models reliably follow ~150-200 instructions before compliance degrades; Claude Code's system prompt already spends ~50; most CLAUDE.md files blow the budget. — https://tianpan.co/blog/2026-02-14-writing-effective-agent-instruction-files
- [asserted] Contradiction harm: conflicting instructions (e.g., two package managers) undermine credibility of the whole file unless declared as overrides. — https://www.agentlint.app/blog/writing-a-good-agents-md/
- [asserted] Wrong-tool-family harm: Claude Code does not read AGENTS.md at all — a repo whose only instructions live in AGENTS.md is silently uninstructed for Claude Code users. Checkable without knowing the project. — https://github.com/cli/cli/issues/14075
- [asserted] Business cost of stale docs (general): new hires take 2-3 months longer to become productive with non-current docs; devs spend 3-10 hrs/week searching for answers that should be documented (2025 GetDX study, via secondary source). — https://hackernoon.com/when-documentation-lies-detecting-drift-between-code-and-reality
- RANKING (frequency x harm, project-agnostic checkability): 1. stale/wrong commands (high freq [asserted most-common tie], highest harm — agent executes, fails, improvises, distrusts file; verifiable against manifest AND by running); 2. dead file paths (high freq, medium-high harm — agent searches wrong place; R13 already covers); 3. architectural/framework claims vs. reality (asserted most-common decay, hardest to notice, checkable vs. lockfile/manifest without project knowledge); 4. contradictory rules (medium freq, harm = whole-file credibility loss); 5. wrong default branch / git-reality claims (lower freq, high harm when hit — wrong-base PRs); 6. bloat past instruction budget (very high freq, diffuse harm). — synthesis of sources above, frequency labels [asserted] except where [measured]

## Q2 — Competitors, stranger angle

- [verified-source] ctxlint (YawLabs) is the closest competitor: `npx -y @yawlabs/ctxlint@latest` runs 41 context checks incl. `paths`, `commands`, `staleness`, `contradictions`, `tokens`, secrets, plus MCP/session/skill checks; premise verbatim: "You rename a file, change a build script, or switch from Jest to Vitest — and your CLAUDE.md still says the old thing." — https://github.com/YawLabs/ctxlint
- [verified-source] ctxlint's `commands` check is STATIC: regex-parses npm/pnpm/yarn/bun/make invocations and validates script names against package.json / builtin-subcommand tables; it never executes a command (src/core/checks/commands.ts). Its `staleness` check is a git-mtime heuristic (context file >14/30 days old while referenced paths kept receiving commits), not a truth check (src/core/checks/staleness.ts). — https://github.com/YawLabs/ctxlint
- [verified-source] ctxlint has NO framework/dependency-claim-vs-lockfile check and NO default-branch check in its check list. — https://github.com/YawLabs/ctxlint
- [asserted] AgentLint (agentlint.app): 51 deterministic checks scoring 6 dimensions (Findability/Instructions/Workability/Continuity/Safety/Harness) + 7 opt-in AI checks; output is a 0-100 score + fix plan; mostly quality heuristics (emphasis-keyword counts, file sizes, naming), reference-resolution is existence-level. Ships as npm global + GitHub Action + Claude Code plugin (`/al`). — https://github.com/0xmariowu/AgentLint and https://www.agentlint.app/
- [verified-source] cclint (@carlrannaberg/cclint): validates agent frontmatter, slash-command definitions, settings.json hooks, and CLAUDE.md "template structure/best practices" — spec/format conformance only, nothing verified against the live repo. — https://github.com/carlrannaberg/cclint
- [asserted] claudeaudit (claudeaudit.dev): an installable SKILL (not a CLI) scoring "agent readiness" across 14 categories / 2 dimensions (config readiness maturity + ergonomics); LLM-judged, not deterministic doc-vs-live verification. — https://claudeaudit.dev/
- [asserted] AgentLinter (agentlinter.com) discovers all workspace .md context files across Claude Code/Cursor/Windsurf etc. — breadth of surfaces, same static class. — https://agentlinter.com/
- COMPETITOR GAP in one line: every linter verifies that referenced things EXIST (static parse vs. manifest); none verifies that documented claims are TRUE — that the command actually exits 0, the framework claim matches the lockfile, the branch claim matches origin/HEAD, the architecture prose matches the tree — Helicon's doc-vs-live lane is empty, but the existence-check tier is already commoditized by ctxlint's one-liner. — [verified-source] synthesis
- [asserted] Validation requires enforcement outside prose: "AGENTS.md can say 'run typecheck before merge.' It cannot make typecheck pass" — linters catch reference rot; only execution catches behavior rot. — https://www.agentlint.app/blog/writing-a-good-agents-md/

## Q3 — Minimum-viable stranger check-set ("first 60 seconds" of npx helicon)

- [inference from ranking + competitor overlap] MVP set, ordered by stranger-value per second: (1) R13 dead-path check (have it); (2) COMMANDS-VERIFIED: extract every documented command, validate vs. manifest, then actually run the safe ones (build/test/lint with timeout, sandboxed) and report which documented commands FAIL — no competitor executes; (3) framework/dependency claims vs. lockfile ("uses Jest" vs. vitest in package.json — ctxlint's own motivating example, which it doesn't actually check); (4) default-branch and git-reality claims vs. origin/HEAD; (5) contradiction pairs (both linters do a version; table stakes); (6) instruction-budget count vs. ~150-200 ceiling with the Claude Code ~50 baseline cited. — synthesis
- [asserted] Copy-pasteable output bar: "commands should be copy-pasteable, paths should exist, referenced files should still be present" — the stranger report must show file:line + the failing claim + the observed truth, zero project knowledge assumed. — https://www.betterclaw.io/blog/agents-md-best-practices
- [inference] The 60-second hook is a LIES FOUND count, not a score: "Your CLAUDE.md makes 23 checkable claims; 6 are false (3 dead paths, 2 dead commands, 1 wrong framework)" — a 72/100 score (AgentLint's model) is advice; a falsified claim with line number is evidence. Strangers keep tools that find true negatives, not tools that grade style. — inference from harm sources above

## Q4 — Distribution for a repo-agnostic CLI in 2026

- [observed-in-category] Every competitor in this exact niche ships the same funnel: zero-install npx one-liner (ctxlint `npx -y @yawlabs/ctxlint@latest`, cclint `npx @carlrannaberg/cclint`) + CI (AgentLint has a GitHub Marketplace Action; cclint advertises CI exit codes) + in-agent surface (AgentLint's Claude Code plugin `/al`; ctxlint's MCP server mode; claudeaudit as a skill). — https://github.com/YawLabs/ctxlint · https://github.com/marketplace/actions/agentlint · https://claudeaudit.dev/
- [asserted] Pre-commit/local hooks drive team adoption only when installation is automatic (husky prepare-script pattern); and local hooks never replace CI — checks that matter must also run on infrastructure the dev doesn't control. — https://www.systemshardening.com/articles/cicd/pre-commit-security-hooks/ and https://stefaniemolin.com/articles/devx/pre-commit/setup-guide/
- [asserted] CI is where agent-adjacent tooling is moving (agents that run inside GitHub Actions are a differentiator per 2026 tooling survey). — https://iceberglakehouse.com/posts/agentic-coding-tools/
- [inference] Ranked for Helicon: (1) npx one-liner with the lies-found demo on the stranger's own repo (the only channel that needs zero prior trust); (2) GitHub Action that fails PRs when a doc claim goes false (retention — the "keep it" half); (3) in-agent skill/MCP surface (where the audience already lives); (4) awesome-list/marketplace listings (discovery amplifiers, not drivers — none of the four competitors is known via lists). — synthesis
- [asserted] The doc-drift-in-CI pattern already has prior art marketed at humans-docs (Claude Code + GitHub Actions catching drift), i.e., the CI-gate framing is legible to buyers. — https://dosu.dev/blog/how-to-catch-documentation-drift-claude-code-github-actions

## Honest verdict

- Demand signal is real: >2/3 of devs believe docs stale [measured, general docs]; four independent context-file linters shipped within roughly a year (ctxlint, AgentLint, cclint, AgentLinter) — a market forming is the strongest evidence strangers care. — sources above
- BUT the existence-check tier (dead paths, dead script names, token counts, contradictions) is already commoditized behind one npx command; a stranger who runs ctxlint first gets 80% of a static Helicon. R13 alone does not clear the bar. — [verified-source] ctxlint
- Helicon's defensible stranger value is exactly one level deeper: EXECUTE and COMPARE — run the documented commands, diff the doc's claims against lockfile/branch/tree reality, and report falsified claims with line numbers. That is the check class a static linter architecturally cannot do and the one no shipped competitor does. If Helicon ships only existence checks, it is a worse-distributed ctxlint and the MAJOR FLOP verdict stands. — synthesis, [verified-source] for the competitor half
